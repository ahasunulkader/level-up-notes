# PHP Documentor (phpDocumentor)

## TL;DR
There are **two separate things** people confuse here. **DocBlocks** (`/** */`) are structured comments that your IDE and static analysis tools read — **no library needed**. **phpDocumentor** is a separate tool that reads those DocBlocks and generates a browsable **HTML documentation website** — like PHP.net or Laravel docs. You should always write DocBlocks. You only need phpDocumentor if you want to generate that website.

---

## The Most Important Distinction

```php
// Regular comment — only humans reading the code see this
// Returns the user or null
function getUser($id) { ... }

/**
 * @param  int       $id
 * @return User|null
 */
function getUser(int $id): ?User { ... }
```

The `/** */` comment above — your **IDE reads it right now**. No library. No install. No command to run.

- VS Code → sees `@return User|null` → autocompletes `$user->getName()` after calling this
- PHPStan → sees `@param int $id` → warns if you pass a string
- Another developer → sees `@throws \RuntimeException` → knows to wrap in try-catch

**phpDocumentor** only comes in when you want to take those same comments and turn them into a full website that anyone can browse — without opening the code files.

---

## What the Generated HTML Docs Look Like

Running `vendor/bin/phpdoc run -d src/ -t docs/api/` produces:

```
docs/api/
├── index.html                      ← Homepage listing all classes
├── classes/
│   ├── OrderService.html           ← One page per class
│   └── UserService.html
├── interfaces/
│   └── MailerInterface.html
├── reports/
│   └── deprecated.html            ← Auto-list of all @deprecated items
└── graphs/
    └── classes.html               ← Visual inheritance diagram
```

Each class page shows — formatted, searchable, with sidebar navigation:
- Full class description
- Every method with its parameters, return type, exceptions
- `@deprecated` warnings highlighted
- `@example` code rendered nicely
- Links between related classes

**It looks exactly like this:** php.net/manual, Laravel API docs, Symfony API docs — all generated by the same kind of tool from DocBlocks in the source code.

**Where it's stored:** wherever you tell it (`-t docs/api/` → `docs/api/` folder). You commit it to your repo or deploy it to a docs server.

## When Do You Actually Need phpDocumentor?

| Situation | Need phpDocumentor? |
|---|---|
| Writing comments for yourself | ❌ No — just write DocBlocks |
| IDE autocomplete & type hints | ❌ No — IDE reads DocBlocks natively |
| PHPStan / Psalm static analysis | ❌ No — they read DocBlocks directly |
| Small/medium private project | ❌ No — DocBlocks alone are enough |
| Open source library | ✅ Yes — users need browsable API docs |
| Large team with internal API reference | ✅ Yes — generated docs stay up to date |
| Client deliverable requiring documentation | ✅ Yes |

**Bottom line:** Most PHP developers write DocBlocks daily and never run phpDocumentor at all. The DocBlocks are still 100% valuable without it.

## Simple vs DocBlock Comment — Side by Side

```php
// ❌ Plain comment — nothing reads this except humans
// Gets user by id, returns null if not found
function getUser($id) {
    return $db->find($id);
}

// Call it:
$user = getUser(1);
$user-> // IDE shows nothing — it has no idea what $user is
```

```php
// ✅ DocBlock — IDE reads this, no library needed
/**
 * Finds a user by their ID.
 *
 * @param  int       $id  The user's unique identifier. Must be > 0.
 * @return User|null      The found user, or null if not found.
 * @throws \InvalidArgumentException If $id is less than 1.
 */
function getUser(int $id): ?User {
    return $db->find($id);
}

// Call it:
$user = getUser(1);
$user->     // IDE now suggests: getName(), getEmail(), getId()
getUser('hello');  // IDE warns: expects int, string given
getUser(1)->getName(); // IDE knows this returns string
```

The DocBlock is doing real useful work — with zero libraries installed.

## Where DocBlocks Are Especially Powerful

PHP's type system can't express everything. DocBlocks fill the gaps:

```php
// PHP type hint says "array" — IDE has no idea what's inside
function processUsers(array $users): array { ... }

// DocBlock tells IDE exactly what's inside
/**
 * @param  User[]             $users    Array of User objects
 * @return array<string, int>           Map of email → user ID
 */
function processUsers(array $users): array {
    foreach ($users as $user) {
        // IDE knows $user is User → autocompletes $user->getEmail()
    }
}
```

Without the DocBlock, `$users` is just "array" — you get no autocomplete inside the loop. With it, the IDE knows every item is a `User`.

## DocBlock Format

A DocBlock is a specially formatted comment that starts with `/**` and ends with `*/`:

```php
/**
 * [Short description — one line, imperative mood]
 *
 * [Long description — optional, detailed explanation of what this does,
 * when to use it, important behavior, etc.]
 *
 * @tag value
 */
```

### Placement Rules
- DocBlocks go **immediately before** the thing they document
- One blank line between DocBlock and what it documents = it's ignored

```php
/**
 * This documents the class below.
 */
class User { // ← immediately after DocBlock

    /**
     * The user's full name.
     */
    private string $name; // ← immediately after DocBlock

    /**
     * Creates a new User.
     */
    public function __construct(string $name) {} // ← immediately after DocBlock
}
```

## Documenting Methods

```php
/**
 * Calculates the discounted price for this user.
 *
 * Applies the user's tier discount on top of any active promotional
 * discount. The higher discount wins — they are NOT stacked.
 * Returns 0.0 if the calculated price would go negative.
 *
 * @param  float  $originalPrice  The original price in the user's currency. Must be >= 0.
 * @param  float  $promoDiscount  Promotional discount as a percentage (0.0–100.0).
 * @return float                  Final price after discounts applied. Always >= 0.
 *
 * @throws \InvalidArgumentException If $originalPrice is negative.
 * @throws \InvalidArgumentException If $promoDiscount is outside 0–100 range.
 *
 * @example
 * $user = new User('Alice', 'premium');
 * echo $user->calculatePrice(100.0, 10.0); // 80.0 (premium=20%, promo=10%, takes higher)
 *
 * @since  1.2.0
 * @see    User::getTierDiscount()
 */
public function calculatePrice(float $originalPrice, float $promoDiscount = 0.0): float {
    if ($originalPrice < 0) {
        throw new \InvalidArgumentException('Price must be >= 0');
    }
    if ($promoDiscount < 0 || $promoDiscount > 100) {
        throw new \InvalidArgumentException('Discount must be 0-100');
    }

    $tierDiscount = $this->getTierDiscount();
    $discount     = max($tierDiscount, $promoDiscount);
    return max(0.0, $originalPrice * (1 - $discount / 100));
}
```

```php
 */
```

## Type Annotations in DocBlocks

DocBlocks extend PHP's type system for complex types — especially useful for arrays:

```php
/**
 * @param  string[]           $emails     Simple array of strings
 * @param  int[]              $ids        Array of integers
 * @param  User[]             $users      Array of User objects
 * @param  array<string, int> $scores     Associative array: string keys, int values
 * @param  array{name: string, email: string} $userData Shaped array
 * @param  list<User>         $userList   Zero-indexed list (no gaps)
 *
 * @return array<int, User>   Key=user ID, Value=User object
 * @return non-empty-string   String guaranteed not empty (for PHPStan)
 * @return positive-int       Integer guaranteed > 0
 * @return User|null          User or null
 * @return never              Method never returns (throws or exits)
 * @return void               No return value
 */
```

### Generic-like Types (Template)

```php
/**
 * A typed collection.
 *
 * @template T
 */
class Collection {
    /** @var T[] */
    private array $items = [];

    /**
     * @param T $item
     */
    public function add(mixed $item): void {
        $this->items[] = $item;
    }

    /**
     * @return T[]
     */
    public function all(): array {
        return $this->items;
    }
}

/** @var Collection<User> $users */
$users = new Collection();
$users->add(new User('Alice')); // IDE knows this is User, not mixed
```

## Documenting Interfaces and Abstract Classes

```php
/**
 * Contract for all payment gateways.
 *
 * Implementations must handle currency conversion internally.
 * All amounts are in the smallest currency unit (e.g., cents for USD).
 *
 * @package App\Payment
 */
interface PaymentGateway {
    /**
     * Charges the customer's payment method.
     *
     * @param  int    $amountCents Amount to charge in smallest currency unit.
     * @param  string $currency    ISO 4217 currency code (e.g., 'USD', 'SGD').
     * @param  string $token       Payment token from the client-side SDK.
     * @return PaymentResult       Result containing charge ID and status.
     *
     * @throws PaymentDeclinedException  If the payment is declined.
     * @throws GatewayException          If the gateway is unreachable.
     */
    public function charge(int $amountCents, string $currency, string $token): PaymentResult;

    /**
     * Refunds a previous charge.
     *
     * Partial refunds are supported — pass an amount less than the original charge.
     *
     * @param  string   $chargeId    The charge ID returned by charge().
     * @param  int|null $amountCents Amount to refund. Null = full refund.
     * @return bool                  True if refund was successful.
     */
    public function refund(string $chargeId, ?int $amountCents = null): bool;
}
```

## phpDocumentor Configuration

```xml
<!-- phpdoc.xml -->
<?xml version="1.0" encoding="UTF-8" ?>
<phpdocumentor
    configVersion="3"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns="https://www.phpdoc.org"
    xsi:noNamespaceSchemaLocation="https://docs.phpdoc.org/latest/phpdoc.xsd"
>
    <title>MyApp API Documentation</title>

    <paths>
        <docs>docs/api</docs>
        <cache>.phpdoc/cache</cache>
    </paths>

    <version number="1.0.0">
        <api>
            <source dsn=".">
                <path>src</path>
            </source>

            <!-- Exclude from docs -->
            <ignore hidden="true">
                <path>src/Migrations</path>
                <path>src/DataFixtures</path>
            </ignore>

            <!-- Only document public API -->
            <visibility>public</visibility>

            <!-- Include @internal items? -->
            <include-source>false</include-source>
        </api>
    </version>

    <template name="default" />
</phpdocumentor>
```

## Integration with Static Analysis

phpDocumentor-style DocBlocks are also read by:

```bash
# PHPStan — finds bugs using your @param/@return types
composer require --dev phpstan/phpstan
vendor/bin/phpstan analyse src/ --level=8

# Psalm — similar to PHPStan
composer require --dev vimeo/psalm
vendor/bin/psalm --init
vendor/bin/psalm

# PHPStorm / VS Code — uses DocBlocks for autocompletion and type warnings
```

```php
// DocBlocks help PHPStan catch real bugs:
/**
 * @param User[] $users
 * @return string[]
 */
function getEmails(array $users): array {
    return array_map(fn(User $u) => $u->getEmail(), $users);
}

// PHPStan will warn if you pass the wrong type:
getEmails(['not', 'users']); // Error: argument expects User[], got string[] given
```

## Best Practices

```php
// ✅ DO — describe WHY and edge cases, not just WHAT (the code already shows WHAT)
/**
 * Returns the user's display name.
 *
 * Falls back to email prefix if name is not set.
 * Returns 'Guest' for unauthenticated users.
 */
public function getDisplayName(): string { ... }

// ❌ DON'T — restate the obvious
/**
 * Gets the name.
 *
 * @return string Returns the name.
 */
public function getName(): string { ... }

// ✅ DO — document exceptions
/**
 * @throws \RuntimeException  If the payment gateway is unavailable.
 * @throws PaymentDeclinedException  If the card is declined.
 */

// ✅ DO — use @deprecated with alternatives
/**
 * @deprecated 2.0.0 Use UserService::findByEmail() instead.
 */
public function getUserByEmail(string $email): ?User { ... }

// ✅ DO — document non-obvious parameters
/**
 * @param int $retries  Number of retry attempts. 0 = no retries.
 * @param int $delayMs  Delay between retries in milliseconds. Must be > 0.
 */
```

## Interview Q&A

**Q: What is phpDocumentor and why should you use it?**
A: phpDocumentor reads DocBlock comments and generates HTML documentation. Beyond the docs site, DocBlocks are used by IDEs for autocompletion (especially for complex array types), by static analysis tools (PHPStan, Psalm) to catch type errors, and by developers to understand what methods do, what they accept, and what they throw — without reading the implementation.

**Q: What is a DocBlock?**
A: A DocBlock is a `/** ... */` comment immediately before a class, method, function, or property. It has a short description, optional long description, and tags (`@param`, `@return`, `@throws`, `@deprecated`). The double-star (`/**`) distinguishes it from regular comments.

**Q: What is the difference between `@param` and `@var`?**
A: `@param` documents function/method parameters. `@var` documents class properties or local variables. `@return` documents what a method returns.

**Q: Why document array types as `User[]` or `array<string, int>` when PHP has `array` type hint?**
A: PHP's `array` type hint is too broad — IDEs and static analyzers don't know what's inside. `User[]` tells them it's an array of User objects, enabling proper autocompletion inside loops (`$user->getName()` gets completed correctly) and type checking. PHPStan and Psalm use these annotations to detect when you pass wrong types.
